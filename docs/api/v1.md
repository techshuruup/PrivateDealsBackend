# API V1

Source of truth: `routes/api.php` under `prefix('v1')` inside headtoken group.

## Investor (`/api/v1/investor`)

### Auth (public within headtoken)

- Register: `auth/register/validate-send-code`, `verify-code`, `set-pin`
- `POST login`
- Forgot password chain
- `POST register-inquiry`

### Authenticated (`auth:investor-api-guard`)

Major groups:

- Company market/detail/news/favorites
- Pre-IPO transactions buy/sell/cancel
- Dashboard (startup + Pre-IPO)
- Documents, MIS, portfolio*, bank-mandate, notifications
- Primary invest + transaction list/detail
- Secondary invest (sell/buy, ROFR, receipts, payment-received)
- Demat, favorites, family
- KYC (broad) + upload subgroup via `CommonKycController`
- Profile / photo / switch-profile
- AIF get/submit
- add-portfolio, contact-us, delete-account, check-mpin, logout

Controllers: `LoginController`, `CommonController`, `CommonKycController`.

## Business (`/api/v1/business`)

- Public: home/startup lists (reuse investor), login, forgot-password
- Auth partner: dashboard, MIS, primary/secondary/Pre-IPO, earnings, profile, channel partners, investors, relation manager, documents, notifications, portfolio*, pending-tasks, logout, delete-account
- Many invest mutations reuse **investor** `CommonController` methods
- Creating a Wealth Manager, Distributor, Retailer, or Institution also creates one self investor (`investor.is_self = 1`) for that partner’s own orders. Relation Manager does not get one and uses the parent partner’s investor. Partner client investor lists exclude `is_self`. Login and profile include `self_investor_id` (null for Relation Manager). This partner API create does not collect CML. Admin web create for Wealth Manager, Distributor, Retailer, and Institution does, and saves that CML KYC on the self investor.

## Startup (`/api/v1/startup`)

- `POST login`
- Auth: `GET dashboard`, `POST logout`
