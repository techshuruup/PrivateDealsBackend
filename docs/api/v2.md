### `GET /api/v2/business/investor`

Auth: `partner-api-guard`. Same list as `GET /api/v1/business/investor` (`Api\V1\Business\CommonController::investorGet` → `InvestorRepository::investorList`).

Query:

- `is_kyc` — required — `All` | `Yes` | `No` (filters `preipo_kyc_status`)
- `is_active` — required — `All` | `Yes` | `No`
- `is_aif` — optional — `All` | `Yes` | `No` (default `All`)
- `relation_manager_ids` — optional comma-separated partner ids. When set, the other rows use those ids instead of the logged-in partner plus their relation managers (same as v1).

Scope for the other rows is the logged-in partner and that partner’s relation managers. Each row is the investor model plus `total_invested`, `no_of_startups`, `commission_earned`, `startup_list`, and `partner_details`, with `partner`, `portfolio`, `city`, `state`, `country`, and `kyc` loaded.

The logged-in partner’s self investor (`investor.is_self = 1` and `partner_id` = this partner) is included when it is not deleted and matches the same `is_kyc`, `is_active`, and `is_aif` filters. That row is first. Every other row stays `is_self = 0` and keeps the v1 order (no extra sort). A self investor that belongs to another partner is not returned. Other partner client lists still omit `is_self`.

### `POST /api/v2/business/investor`

Auth: `partner-api-guard`. `Api\V2\Business\CommonController::investorCreate`. `POST /api/v1/business/investor` is unchanged.

Body:

- `investor_type` — required — `Individual` | `Hindu Undivided Family` | `Private Limited` | `Public Limited` | `Partnership` | `Proprietorship` | `Limited Liability Partnership`
- `name` — required string, max 255 — stored as `ucfirst(trim())`
- `mobile_number` — required numeric
- `email` — optional email — stored as `strtolower(trim())`; blank or omitted stored as null
- `gender` — optional — `Male` | `Female` | `Other` — stored only when sent

Password, address, city, and pincode are not collected. Access flags and CML are not accepted.

`partner_id` is the logged-in partner. `created_by` and `updated_by` are that partner’s `created_by`. `registration_step` is `3`. `mobile_country_code` is `91`. A `referral_code` is generated. `is_self` is `0`. `is_primary_access`, `is_secondary_access`, and `is_preipo_access` are copied from the partner. Password stays null on a new row. Address, `city_id`, `state_id`, `country_id`, and `pincode` stay null.

`mobile_number` must be unique among investors with `is_deleted` = `0` and `registration_step` = `3`. `email` uses that same uniqueness rule only when it is sent.

If a non-deleted incomplete row already exists for that `mobile_number` and `mobile_country_code` `91` with `registration_step` not `3`, that row is updated instead of inserting a second investor. Partner ownership, `registration_step` `3`, access flags, name, type, email, and gender are still applied. An existing password on that incomplete row is left as-is.

Success (`status` `1`): message `Investor Created`. `data` is the investor row (`password` hidden). Validation failure (`status` `0`): the first error message.

### `POST /api/v2/business/investor/kyc/cml/read`

Auth: `partner-api-guard`.

Parses a CML PDF for one investor. Same file rules and response as `POST /api/v2/investor/forge/read/demat-pdf` (`DematPdfParsingService::processPdf`). Does not set `preipo_kyc_status`.

Multipart body:

- `investor_id` — required integer. Must belong to the logged-in partner: not deleted, and either `is_self = 0` with `partner_id` equal to this partner or one of their relation managers (same scope as `GET /api/v2/business/investor`), or `is_self = 1` with `partner_id` equal to this partner. Another partner’s investor is rejected.
- `cml` — required PDF, max 10 MB.

Success `data`: `dp_id`, `client_id`, `pan_no`, `account_holder_name`, `account_number`, `ifsc_code`, `bank_name`, `dob`.

A failed parse follows the investor V2 path for that `investor_id`: temp CML file when the parser stores one, plus a pending `demat_manual` row and the pending-KYC admin notification. KYC stays unmarked.

### `POST /api/v2/business/investor/kyc/cml/save`

Auth: `partner-api-guard`.

Saves demat, PAN, optional bank, and optional CML onto the given investor (`DematKycService::saveDematKyc`). Sets that investor’s `preipo_kyc_status = 1`. Same fields as `POST /api/v2/investor/kyc/upload/demat-bank`. `investor_id` uses the same ownership rule as read.

Multipart body:

- `investor_id` — required integer
- `dp_id` — required
- `client_id` — required
- `pan_no` — required
- `name` — required
- `account_number` — optional
- `ifsc_code` — optional
- `bank_name` — optional
- `dob` — optional — `d-m-Y`
- `cml_file` — optional PDF (admin document size limit)

### `POST /api/v2/business/pre-ipo/buy`

Partner-page copy: [partner.md](partner.md). Auth: `partner-api-guard`. `Api\V2\Business\CommonController::preIpoBuy`.

Places one or more Pre-IPO buy orders. Every item is checked before any insert. One failure returns `status` `0` and inserts nothing. Success is one database transaction, one `pre_ipo_transaction` row per item.

JSON body:

```json
{
  "orders": [
    { "deal_uuid": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d", "investor_id": 2, "shares": 10, "share_price": 102 }
  ]
}
```

- `orders` — required array, minimum 1
- `deal_uuid` — required uuid from the company deal list. Deal must be not deleted, not expired, `status` `available`, `deal_type` `sell`, and `created_by_partner_id` set. A null `created_by_partner_id` is rejected (no seller fallback). `company_id` on the order is the deal’s `company_id`. A numeric `deal_id` does not select the deal.
- `investor_id` — required integer. Same access as `GET /api/v2/business/investor`: not deleted, and either a non-self investor of this partner or one of their relation managers, or this partner’s self investor. Another partner’s investor is rejected.
- `shares` — required integer, minimum 1, and at least the deal `minimum_qty`. When `available_quantity` is greater than 0, shares must not exceed it. Repeated `deal_uuid` values are combined and must still fit. `available_quantity` is not decremented.
- `share_price` — required numeric. The final price this partner quotes the investor. No minimum against the deal price.

Not accepted from the client (ignored if sent): `deal_id`, `distributer_price`, `payment_mode`, `is_distributer`, `seller_id`, `partner_id`. No coupons.

Saved on each row (`status` stays `0`, `order_step` is `mandate_pending`):

| Column | Value |
|--------|--------|
| `investor_id` | Client on the item |
| `company_id` | Deal `company_id` |
| `deal_id` | Deal id |
| `partner_id` | Deal `created_by_partner_id` (the Institution), not the logged-in partner |
| `seller_investor_id` | Institution self investor (`investor.partner_id` = that Institution, `is_self` = 1, not deleted). Missing self investor rejects the item |
| `seller_id` | null |
| `base_price` | Deal `base_price` (example 99, what the Institution entered). Null `base_price` rejects the item |
| `distributer_price` | Deal `share_price` (example 100, base plus admin processing fee) |
| `share_price` | Item `share_price` (example 102) |
| `investment_amount`, `payable_amount` | `shares * share_price` |
| `is_distributer` | true |
| `payment_mode` | `RTGS` |
| `instrument` | `equity` |
| `order_step` | `mandate_pending` |

The partner keeps `share_price - distributer_price` per share (102 − 100 = 2). The Private Deals fee is inside `distributer_price` (100 − 99).

Success (`status` `1`): message `Orders placed successfully.` when the buy mandate is sent. If Digio fails, the order is still saved and the message is `Orders placed. The buy mandate could not be sent.` Printed mandate expiry is 7 days after `created_at`. Later steps are `order_step`, not integer status. Each item in `data` is the order-step object below, plus `mandate_sent`. Field-level cancel, receipt, and confirm routes: [partner.md](partner.md). Institution actions: [institution.md](institution.md).

### Order-step list and detail object

Used when `pre_ipo_transaction.order_step` is set, on:

- `GET /api/v2/business/pre-ipo/transaction-list` (that row only; a null `order_step` row on the same page still has `status_list`)
- `GET /api/v2/business/pre-ipo/transaction/detail`
- `GET /api/v2/business/institution/pre-ipo/transaction`
- `GET /api/v2/business/institution/pre-ipo/transaction/detail`

Institution list and detail never include a null `order_step` row, and they hide `mandate_pending` plus cancelled orders that never reached `share_confirmation_pending`.

The object does not include `status_list`, `current_status`, integer `status`, `percentage`, `is_processing`, `deal_slip`, `approval_file`, `rejection_file`, or a `seller_master` bank. `current_step` and `next_step` come from `PreIpoOrderStepHelper::labels` for the caller (buying partner or Institution).

Keys: `id`, `transaction_invoice_no`, `order_step`, `current_step`, `next_step`, `action`, `sign_link`, `investor` (`id`, `name`), `company` (`id`, `brand_name`, `logo`), `deal_id`, `shares`, `base_price`, `distributer_price`, `share_price`, `investment_amount`, `payable_amount`, `cancellation_reason`, `payment_details`, `payment_receipt`, `share_transfer_receipt`, `created_at`.

`sign_link` is the mandate link on `mandate_pending` or the deal-slip link on `deal_slip_pending`, and only when that link exists for the buying partner’s self investor. It is null for the Institution. `payment_details` is null before `payment_pending`. From `payment_pending` it is `amount` plus `account` (`account_holder_name`, `bank_name`, `account_number`, `ifsc_code`) from the Institution self investor’s CML bank (`seller_investor_id`), or `account` null when that row is missing. Receipt keys are null until a file is stored. `cancellation_reason` is null unless `order_step` is `cancelled`.

## Seller (`/api/v2/seller`)

Auth actor: `SellerMasterModel` (`seller_master` table) via `seller-api-guard`.

Login credentials live on `seller_master` (`mobile_number`, `password`, etc.) — set from Admin seller create/edit.

Profile/login payload includes feature access flags (same names as investor): `is_primary_access`, `is_secondary_access`, `is_preipo_access`.

**Seller dashboard** (`GET /api/v2/seller/dashboard`):

- `summary.transactions`: `pending` / `processing` / `completed` (same buckets as seller Pre-IPO list; scoped to `seller_id`)

**Seller update share price — body:**
```
{
  "prices": [ // array required — min 1; each item = one company quote
    {
      "company_id": 12, // integer required — approved company; distinct within request
      "sell_price": 100.5, // numeric required — min 0
      "buy_price": 98, // numeric optional — min 0
      "min_qty": 10, // integer required — min 1
      "total_qty": 500 // integer optional — min 1; if set must be >= min_qty
    },
    {
      "company_id": 15, // integer required
      "sell_price": 55, // numeric required
      "min_qty": 5 // integer required
    }
  ]
}
```
All-or-nothing: invalid row rejects the whole request. Each success appends a `seller_company_share_price` history row (`seller_id` from auth, `date` = today) and sets `company.is_price_updated_today=1` for those companies. Daily reset via `app:company-share-price-update-today-change` (also clears admin `price_updated_today`).

**Seller Pre-IPO transactions** (scoped to `pre_ipo_transaction.seller_id` = authenticated seller; outside `company` routes):

| Method | Path | Auth |

| GET | `/api/v2/seller/pre-ipo/transaction` | `headtoken` + Bearer |

**List query params:**
- `status` — optional — `pending` \| `processing` \| `completed`
  - `pending` = admin market: `created_by IS NULL` AND `status = 0`
  - `processing` = admin pending: `status > 1` AND `status != 5`
  - `completed` = admin completed: `status = 5`
- `company_id` — optional — exact company id
- `company` — optional — partial match on company `brand_name`
- `skip` / `take` — optional pagination (default take = `app_pagination_limit`)

Each list/detail row includes `status_list` from `PreIpoTransactionHelper::getStatusListForApplicationV2`. Detail requires `transaction_id` and returns only the calling seller’s transaction.
